Built on a boring, fast stack

The business chain, on a foundation you can inspect.

One model definition is the single source of truth. From it Meshble generates the database schema, a typed REST API, an OpenAPI spec and an agnostic UI contract: no hand-written endpoints, no drift, no frontend welded to the backend. The whole chain (sales, purchase, inventory, accounting) sits on an inspectable metamodel compiled at build time, with secure CRUD that runs in one place.

Every model is a contract

Declare a struct; the macro emits an inspectable descriptor. Migration, a REST resource, an OpenAPI schema and a UI contract are derived from it. No hand-written endpoints, no drift between API and UI. 

#[model(name = "sale.order")]
struct SaleOrder {
  #[field(required)] partner_id: Many2one,
  #[field(compute = "sum", store)] amount_total: Decimal,
  line_ids: One2many,
}  // => GET/POST /api/sale.order, /view, /action/*, /report/*

Secure by default

Access control, record rules and multi-company isolation are enforced on every secured read and write. A posted journal entry freezes; a salesperson cannot touch another company's ledger.

Double-entry accounting

account.move with a balanced-entry constraint, per-journal numbering, and invoices posted straight from a sales order.

Wizards & reports

Transient models with a GC cron, and an HTML-first report engine with a PDF rasterization seam behind a trait.

Mail, cron, attachments

A chatter thread per record, scheduled jobs, and content-addressed blob storage, all opt-in with one line.

From struct to running ERP.

define

Write the model

A Rust struct with field attributes. Compile-time registries pick it up; the metamodel is data you can inspect, not a class synthesized at runtime.

serve

Migrate & serve

One CLI migrates in dependency order and serves the secured REST API, the OpenAPI spec and the per-model UI contract.

use

Build any UI

The bundled React app renders lists, forms, wizards and reports straight from the contract. Or wire your own client to the same API.

Meshble is not a turnkey suite, and it does not pretend to beat decades of enterprise software on breadth. It competes on a different axis: a small, typed, open core you own and integrate. Here is where that genuinely wins, and where a mature platform still does.

Reach for Meshble when

You want a typed, headless core to build a product or internal tools on; you self-host and dislike per-user fees; you will write modules in Rust and value compile-time safety and a clean generated API over a ready-made catalog.

Look elsewhere when

You need a turnkey suite with thousands of ready apps today (Odoo), deep industry processes and a global support org (SAP), a CRM-led sales motion (Salesforce), or enterprise ITSM (ServiceNow). Meshble is young: a small module set and no partner network yet.
