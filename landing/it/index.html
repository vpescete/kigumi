Meshble è un framework ERP headless, guidato dallo schema, scritto in Rust. Definisci un modello e ottieni gratis una REST API tipizzata e una UI.

Costruito su uno stack noioso e veloce

La catena del business, su una base che puoi ispezionare.

Una sola definizione di modello è l'unica fonte di verità. Da essa Meshble genera lo schema del database, una REST API tipizzata, una specifica OpenAPI e un contratto UI agnostico: niente endpoint scritti a mano, niente drift, niente frontend saldato al backend. L'intera catena (vendite, acquisti, magazzino, contabilità) poggia su un metamodello ispezionabile compilato a build time, con CRUD sicuro che gira in un unico posto. Quel core compilato è il pavimento, non il soffitto: campi, regole di accesso e ritocchi alle viste si aggiungono dal database o dall'API su un server in esecuzione, senza ricompilare e senza riavviare.

Ogni modello è un contratto

Dichiara una struct; la macro emette un descrittore ispezionabile. Migrazione, risorsa REST, schema OpenAPI e contratto UI ne derivano. Niente endpoint scritti a mano, niente drift tra API e UI. 

#[model(name = "sale.order")]
struct SaleOrder {
  #[field(required)] partner_id: Many2one,
  #[field(compute = "sum", store)] amount_total: Decimal,
  line_ids: One2many,
}  // => GET/POST /api/sale.order, /view, /action/*, /report/*

Sicuro per impostazione predefinita

Controllo degli accessi, record rules e isolamento multi-azienda sono garantiti su ogni lettura e scrittura protetta. Una registrazione contabile confermata si congela; un commerciale non può toccare il libro mastro di un'altra azienda.

definisci

Scrivi il modello

Una struct Rust con attributi sui campi. I registry a compile-time la raccolgono; il metamodello è un dato che puoi ispezionare, non una classe sintetizzata a runtime.

servi

Migra e servi

Una sola CLI migra in ordine di dipendenza e serve la REST API protetta, la specifica OpenAPI e il contratto UI per ogni modello.

usa

Costruisci qualsiasi UI

L'app React inclusa renderizza liste, form, wizard e report direttamente dal contratto. Oppure collega il tuo client alla stessa API.

Estendilo senza ridistribuire.

Il core tipizzato è il pavimento, non il soffitto. Aggiungi un campo, una regola di accesso o una modifica a una vista direttamente dal database o dall'API, e ha effetto sul server in esecuzione. Senza ricompilare, senza riavviare, senza script di migrazione scritti a mano. Questa è la metà framework di Meshble: la sicurezza di un core compilato con la portata di una piattaforma che rimodelli a runtime.

campo

Aggiungi una colonna, dal vivo

POST di un campo a un modello. Ottiene una colonna Postgres reale e compare nel contratto che ogni client legge, senza ricompilare.

POST /api/product.product/_fields
{ "name": "warranty_months",
  "kind": "integer" }
# => { "added": "warranty_months" }
regola

Cambia l'accesso, dal vivo

POST di una record rule o di una ACL. Il dominio è validato contro il modello, poi entra nello stesso engine che ogni lettura sicura già esegue.

POST /api/_rule
{ "model": "sale.order",
  "domain": { "field": "state",
    "op": "=", "value": "sale" } }
vista

Rimodella il form, dal vivo

POST di un override di vista per rinominare, nascondere, bloccare o cambiare widget a un campo. Si fonde nel contratto UI come post-pass, senza toccare il frontend.

POST /api/res.partner/_view
{ "field": "email",
  "label": "Email contatto",
  "readonly": true }

Ambito onesto: oggi i campi a runtime sono scalari e gli override di vista sono presentazionali. Relazioni e visibilità condizionale sono nella roadmap. La logica di business profonda resta nei moduli compilati e tipizzati, dove deve stare.

Un confronto onesto.

Meshble non è una suite chiavi in mano e non pretende di battere sull'ampiezza decenni di software enterprise. Compete su un altro asse: un core piccolo, tipizzato e aperto che possiedi e integri. Ecco dove questo vince davvero, e dove una piattaforma matura resta avanti.

Scegli Meshble quando

Vuoi un core tipizzato e headless su cui costruire un prodotto o strumenti interni; fai self-hosting e mal sopporti i costi per utente; scriverai moduli in Rust e dai valore alla sicurezza a compile time e a un'API generata pulita più che a un catalogo pronto.

Guarda altrove quando

Ti serve una suite chiavi in mano con migliaia di app già pronte (Odoo), processi di settore profondi e una rete di supporto globale (SAP), una macchina di vendita guidata dal CRM (Salesforce) o un ITSM enterprise (ServiceNow). Meshble è giovane: pochi moduli e nessuna rete di partner, per ora.
